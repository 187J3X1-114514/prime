## 数学等价但规模较大的生命周期与架构工作

- 维护一个按真实 timeline 完成点循环复用的光追描述符资源环。TLAS 替换目前会创建新的描述符池
  和描述符集，再退休旧资源，以保证仍在执行的命令缓冲有效。资源环可以只在某个描述符集真正完成
  后更新它，从而在不改变渲染结果的情况下避免驱动分配抖动，但这需要与 NRD 帧绑定同等严格的
  所有权协议。
- 将 Section 几何和灯光记录直接写入 staging 或原生输出存储。当前分支已经删除多余的最终复制，
  使用任意数量的 CPU segment 表示一个逻辑 cluster，同时保持单 BLAS/TLAS instance，并避免长期
  保留 CPU 灯光数据。所有 segment 在原子 generation 提交前仍持有 Java 基本类型数组；直接写入
  可增长原生存储可以保持数学等价，同时降低 Section→cluster 所有权转移期间的重复驻留。

## 调试叠加层

考虑加入可开关的实时调试叠加层，直接显示用于调色和曝光判断的画面数据，例如测光亮度、
自动曝光目标与当前 EV、最终曝光 EV、HDR 亮度范围和裁剪比例。叠加层应只读取已有渲染
状态，不改变曝光历史、路径追踪累积或最终输出。

## NVIDIA Streamline

评估并集成 NVIDIA Streamline，统一 NVIDIA 后处理功能的运行时接入、能力探测、资源标记
和生命周期管理，同时保留不支持该运行时或功能时的明确回退路径。

## 非标准资源包的 LabPBR 检测

改进基于 `texture.properties` 的 LabPBR 检测方式。当前识别契约与部分未遵循标准声明方式的
资源包不兼容，需要收集实际样本，区分声明缺失、路径差异和属性格式差异，并设计不会把普通
纹理误判为 LabPBR 的兼容检测或显式覆盖方式。

## 高分辨率材质下的纹理体素表面

系统检查高分辨率资源包的性能和兼容性，并据测量结果设计明确的上限或降级策略：

- 分别以 16、32、64、128、256 像素方块纹理测量 3×3×3 细节窗口的 CPU 建网时间、
  BLAS 构建时间、峰值 staging/显存、可复用 mesh 数量和 TLAS instance 数量。
- 审核平方级 texel/三角形增长、动画帧、非正方形帧、混合分辨率的 LabPBR/base 纹理、
  atlas padding/mipmap、最大 Vulkan 图像尺寸及所有字节数和 primitive 数溢出边界。
- 验证大 atlas 上基础色、LabPBR 和 alphacut opacity micromap 的逐 texel 寻址精度，
  并覆盖资源重载、动画换帧和编译 cluster 缓存往返。
- 在测量基础上决定逐材质分辨率上限、保形降采样或回退普通宏面的策略；降级必须可诊断，
  且不能静默改变透明度、材质 UV 或向外位移上限。
