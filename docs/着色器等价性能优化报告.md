# 着色器等价性能优化报告

## 范围

本报告覆盖 GPU/shader 路径及其编译装配边界，包括参考累积、实时积分、NRD 前后处理、DLSS Ray Reconstruction 准备和光追管线创建。没有优化 CPU 热路径；生产 Java 的改动仅用于消除驱动重复编译和承载 SBT 阶段选择。没有修改受保护的 `robocute_bsdf_*.glsl` 参考移植，也没有实施改变采样方差或引入实时偏差的方案。

允许的差异仅为数学等价重排；非边界输入由现有 GPU 属性测试验证。可能改变方差或引入偏差的候选方案单独记录在《着色器性能优化-未实施的方差与偏差方案》。

## 主要改动

### 参考累积

- 增加只返回总辐射和首表面距离的参考积分路径。
- 参考路径继续使用相同的 BSDF、MIS、介质栈、俄罗斯轮盘赌和透明首界面固定双分支。
- 不再为参考累积构造三套降噪 guide、反射信号分区或 8 层 PSR delta 链。
- 透明固定分支增加无 guide 的适配入口；属性测试逐字段比较它与实时入口的方向、响应、PDF、相对折射率、事件和介质栈。

### 实时积分

- 太阳、星图和面积光按顺序求值，避免全部 Sobol 样本及多个光照分解结构同时存活。
- 可降噪表面的能量 guide 与 BSDF 采样共享一次 RoboCute 状态初始化。
- 同一直接光样本的可见性判断和 BSDF 求值复用着色法线；透明求值复用外向法线。
- 缓存 guide 所需的粗糙度和法线，避免 LabPBR 解码及法线解包在同一表面重复执行。
- 数值诊断关闭时，在分类前退出，不再在正常显示模式执行 NaN、Inf、范围和方向分类。

### NRD

- 将 raygen 到 `nrd_motion.comp` 的私有 scratch 契约作为单一验证边界；前处理不再重复消毒已经有限且限幅的 albedo、hit distance、方向和 packed normal。
- 增加经过消毒数据的 demodulate、双信号联合限幅、hit-distance 归一化和打包入口，并用稳健入口逐 bit 对照。
- 运动矩阵计算与辐射 demodulate 重排为不重叠的值生命周期。
- 天空和无效反射 guide 提前退出；SH1 两个方向都为空时跳过四邻域深度、法线读取和 re-jitter。
- 合成阶段只在反射 guide 有效时读取反射 specular material 与反射 SH 数据。

### DLSS Ray Reconstruction

- 天空走独立短路径，不读取表面位置、法线、noisy diffuse/specular 或太阳信号。
- 表面颜色在运动矩阵投影前完成并写出，避免多个辐射向量跨两次投影保持存活。
- 消除 raygen 已经保证的重复有限性、范围和 FP16 限幅检查。
- primary 与虚拟反射 motion 仍保留矩阵结果的有限性检查，因为矩阵和 GPU 投影属于外部边界。

## 首次驱动编译优化

一次冷启动日志记录到以下基线：

- 主机有 32 个逻辑处理器；驱动报告最多 10 路并发，Prime 因而使用 10 个编译线程。
- 光追管线驱动编译耗时 489,945 ms，约 8 分 10 秒。
- 同一工作区离线执行完整 GLSL→SPIR-V 编译只需约 7–23 秒。因此约 10 分钟的主要瓶颈是 NVIDIA 驱动对大型 raygen 的优化与机器码生成，不是 Gradle、glslang 或 CPU 线程选择。

旧管线为截图、wavefront head、step、transition 和 tail 分别提交一个大型 raygen 编译单元。后四者都嵌入几乎相同的积分器、BSDF 和灯光实现；step 与 transition 仅有尾部灯光策略参数不同。

当前管线保留 5 个可独立寻址的 SBT raygen group，但只使用 2 个 shader stage：

- `world` 只负责截图/参考累积，不再携带不可达的实时 megakernel。
- head、step、transition 和 tail 合并为一个 `wavefront` stage，由每个 SBT record 后的 32-bit 阶段值选择入口。
- tail 在 SER permutation 中显式使用无重排 trace，保留原有“稀疏尾部不执行 SER 重排”的性能策略。
- SBT raygen stride 计入 shader handle 后的阶段数据，避免最大尺寸 handle 与内联数据重叠。

发布包中的 SPIR-V 数量从 27 个降到 21 个。当前运行时选用的 SER raygen 总字节数从 2,126,160 降到 776,048，减少 63.5%：

| SER raygen | 旧字节数 | 当前字节数 |
|---|---:|---:|
| 截图/参考 `world` | 449,360 | 337,108 |
| wavefront 合计 | 1,676,800 | 438,940 |
| 总计 | 2,126,160 | 776,048 |

构建期同时增加函数内保守 DCE，移除已静态确定的模式分支、未消费的聚合字段和冗余插入；不做激进内联，也不改变仍存活的浮点表达式顺序。该变化既缩小驱动输入，也进一步降低 NRD/RR 的静态局部变量和 store 数量。

以上字节数和编译单元数量能证明重复输入已显著减少，但不能直接换算成驱动耗时。改造后的真实冷启动耗时仍以目标机器下一次清空/失效 pipeline cache 后的日志为准。

## 本轮等价热路径优化

- 实时积分把 view direction、发光临时量、太阳样本和非太阳直接光拆成更短且互不重叠的生命周期；两个主积分函数各减少一个重复的非 delta 判断。
- `nrd_composite` 的透明非反射短路径在读取法线、粗糙度、位置和执行 view normalize 前退出；SH 方向有效性改用平方长度，消除两次平方根。
- `rr_prepare` 在完成颜色与 aerial 合成后才读取 primary position，避免该 `vec4` 跨越整段照明计算。
- 太阳方向由 Java 适配边界保证为单位向量；太阳查询、太阳采样基和星图映射不再逐顶点重复 normalize。属性测试随机覆盖 16,384 个太阳轨道角。

调试 SPIR-V 中两个主要实时积分函数的函数局部代理均小幅下降：

| 函数 | 指令 | 局部变量 | load | store | call |
|---|---:|---:|---:|---:|---:|
| `primeIntegrateWithVolume` 基线 | 1,644 | 244 | 217 | 345 | 87 |
| 当前 | 1,641 | 243 | 217 | 344 | 86 |
| `primeIntegrateWavefrontSurface` 基线 | 950 | 130 | 125 | 173 | 48 |
| 当前 | 947 | 129 | 125 | 172 | 47 |

## 验证

- `verifyRoboCutePort` 通过，受保护参考文件未改动。
- 发布 shader 与 SER permutation 均通过 `glslangValidator` 和 `spirv-val`。
- GPU 属性测试覆盖稳健/可信 NRD 入口逐 bit 一致、透明固定分支逐字段一致，以及既有 BSDF、材质、传输、LUT 和分布性质。
- `gradlew check shaderTest` 全部通过。

## 目测与性能验收重点

1. 分别测试参考累积、NRD 和 DLSS RR，不只测试默认实时路径。
2. 覆盖天空、普通不透明表面、玻璃、水面、水下、透明掠射角和多层透明。
3. 检查太阳反射拖影、透明后首表面稳定性、相机平移/旋转及静止收敛。
4. 记录 raygen、`nrd_motion`、`nrd_composite` 和 `rr_prepare` 的 GPU 时间。
5. 用 Nsight 对比寄存器数、occupancy、local-memory spill、图像 load/store 和分支效率。
6. 若参考路径的驱动首次编译时间明显增加，优先评估独立预编译 pipeline；不要回退为游戏内按需编译。
