# 确定性纯渲染流水线架构（草案）

## 目的与边界

Prime 的长期方向是把渲染定义为显式输入到显式输出的确定性变换。对任一合法输入，
在相同平台、二进制和配置下，各阶段输出都应可逐 bit 重放；随机采样只扩大输入空间，
不允许制造不可复现的执行结果。

这里的“纯”是逻辑语义，不要求取消 GPU 资源、命令提交等必要副作用。副作用必须集中在
Minecraft 捕获、GPU 驻留和设备执行三个边界；场景编译、帧计划、积分器语义、重建输入
准备和历史转移不得读取隐藏状态。

本架构首先保证数据流、单位、坐标、资源身份、生命周期和重放正确性，不以验证 NRD、
FSR 或 DLSS 的降噪能力为目标，也不要求为测试牺牲生产性能。逻辑阶段可以在执行器中
安全地原地复用同一 GPU 图像。

## 已成为事实的基线

- `RayTracingRuntime` 是渲染接管和失败回退的唯一生命周期入口；Mixin 只负责 Minecraft
  接入和设备协商。
- `render/terrain` 已以 Section 快照为异步网格化输入，以 virtual cluster 为 BLAS、
  TLAS instance、灯光树叶、generation 和清退单位；新 generation 完整建立后才替换旧
  场景。
- `render/vulkan` 独占 Vulkan 句柄、VMA、同步、加速结构、descriptor、pipeline 和延迟
  退休。热路径不使用 `vkDeviceWaitIdle`，历史只在实际提交后推进。
- 实时与截图共用固定 12 轮、两个稳定路径槽和紧凑活动队列的 wavefront 主积分器。
  `PathState`、`SurfaceInteraction`、BSDF、PDF、采样维度和 reconstruction guide 已是
  显式契约；调度层不重解释积分器数学。
- `WavefrontSignals` 是物理样本到 NRD-FSR、DLSS RR、无后处理和截图适配器的公共图像
  边界；`RealtimePostProcessor` 已显式拥有后端尺寸、jitter、history、record/submitted
  生命周期和线性 HDR 输出。
- `shaders/abi.json` 是 Java/GLSL 布局、工作色彩空间和关键常量的唯一声明源；RoboCute
  移植保持受保护的固定参考边界。
- GPU 属性测试已经用固定 seed 执行真实生产 GLSL，并要求失败输入可重放；当前主要覆盖
  数学片段，尚未覆盖真实积分器到重建输入的完整阶段语义。

当前 `VulkanRenderer` 仍同时承担 Minecraft 状态读取、帧参数组装、命令编排和呈现；
`NrdDenoiser` 仍同时拥有 wavefront 原始目标、NRD 输入准备、原生 dispatch 和合成，并
原地改变部分图像语义。这两处是下一步拆分边界，不应被文档误写为已完成。

## 目标数据流

```text
Minecraft live state
  └─ MinecraftCapture.read                         [副作用]
       → MinecraftSnapshot + AssetSnapshot
  └─ SceneCompiler.compile                         [纯函数]
       → CompiledScene
  └─ SceneUploader.upload                          [副作用]
       → ResidentScene

ResidentScene + FrameInput
  └─ Integrator.plan                               [纯计划]
       → RenderPlan
  └─ RenderDevice.execute                          [副作用]
       → RawWavefrontFrame
  └─ NrdInputPreparer.prepare                      [纯语义]
       → PreparedNrdFrame
  └─ ReconstructionBackend.execute                 [显式历史]
       → ReconstructedFrame + NextHistory
  └─ Composite/Display                             [纯语义 + 设备执行]
       → LinearFrame / DisplayFrame
```

`MinecraftSnapshot` 是对 live world、模型和资源状态的一次不可变捕获；读取 live 对象是
副作用，从快照开始的 mesh、面合并、旋转、材质、OMM、灯光列表和树构建必须只由输入
决定。`CompiledScene` 保存稳定排序的内容数据，不包含偶然的 Java 对象身份或 GPU 句柄。

`FrameInput` 至少显式包含相机及历史相机、场景版本、尺寸、sample index/epoch、随机种子
或采样序列、jitter、太阳、相机介质、材质与灯光设置、重建模式和历史重置条件。系统
时间、全局单例、未提交帧和可变配置不得成为隐式输入。

阶段类型必须表达语义和生命周期：

```text
RawWavefrontFrame → PreparedNrdFrame → DenoisedFrame → CompositedFrame
```

物理执行器可以让这些逻辑版本别名到同一图像，但 API 不得允许 raw/prepared 混用、
重复准备或越过必要 barrier。历史同样采用 `HistoryInput → NextHistory`，且只有成功提交
后才能成为下一帧输入。

## 确定性契约

1. 随机状态由稳定的像素、样本、路径槽、bounce、分支和 seed 寻址，不依赖活动队列
   索引、atomic 返回顺序、线程调度或墙钟时间。
2. 场景编译中的集合遍历、primitive、instance、材质、纹理、OMM 和灯光顺序必须稳定。
   缓存只影响成本，不影响产物。
3. Shader 写入必须无数据竞争。跨 invocation 的浮点原子累加或无序归约需要改为单写者、
   固定归约树或与顺序无关的表示；队列顺序不得改变路径结果。
4. 同一合法 replay 在同一平台上重复执行时，各阶段内容哈希必须一致。平台指纹包括
   GPU/驱动、Vulkan 特性、SPIR-V、原生库、资源格式和特化配置。
5. 完全重合且等距的 primitive、未初始化资源和未定义同步不属于合法输入。Minecraft
   确实需要的叠层面必须由场景编译器给出确定表示，不能依赖硬件 traversal 的等距命中
   顺序。
6. 开放后端的显式永久池可作为历史值管理。闭源后端若不公开内部状态，严格契约止于
   输入、reset 和特定运行时的实测输出，不伪造可序列化保证。

## 副作用与所有权

- `MinecraftCapture`：唯一允许读取 live Minecraft 状态的边界，输出不可变且自洽的快照。
- `SceneUploader`：唯一把 `CompiledScene` 变为 GPU 驻留资源的边界；资源具有单一所有者，
  通过替换后提交和 timeline 完成点退休。
- `RenderDevice`：唯一创建临时资源、记录/提交命令和回读结果的边界。算法模块只产生
  输入验证、资源需求和 dispatch/trace 计划。
- reconstruction backend：历史所有权必须集中；录制中的 frame token 不得修改已提交
  历史，失败提交不得推进状态。

共享可变全局状态、跨阶段隐藏写入和以对象身份表示语义均不允许。性能所需的 descriptor
复用、图像别名和暂存池属于执行器内部优化，不能改变逻辑版本或可观察结果。

## 重放与语义测试

`RenderReplay` 应保存足以从选定边界独立执行的最小输入：

- 平台指纹以及 shader/native/resource 哈希；
- `MinecraftSnapshot` 或 `CompiledScene`；
- 一帧或一段 `FrameInput`；
- 显式历史输入和预期 reset；
- 失败阶段及必要的中间产物。

生产帧执行器提供可选捕获点，至少位于 wavefront resolve 后和 reconstruction dispatch
前。正常运行不分配 readback、不增加 dispatch；测试在低分辨率真实场景中运行生产
SceneCompiler、BLAS/TLAS、wavefront 和输入准备，再回读真实阶段输出。

核心测试分为：

- 纯函数属性测试：快照编译、布局、状态转移、矩阵和输入适配；
- 真实渲染语义测试：position、normal、material、hitT、SH、view-Z、MV、主/反射/透明
  资源身份及 NaN/Inf；
- 确定性测试：同一 replay 多次执行并逐 bit 比较每个阶段，定位第一个分歧；
- 回归 replay：线上或目测问题缩小为固定输入后永久保留。

NRD 测试的权威观察点是生产积分器实际生成并即将绑定给 NRD 的图像，而非测试代码伪造
的理想输入。重点验证 `old = new + MV`、像素单位、view-Z 差、jitter、虚拟表面、材质
分类、resource identifier 和 history 提交语义；不把 NRD 的收敛速度作为主要门禁。

## 渐进式落地顺序

1. 定义不可变 `MinecraftSnapshot`、`AssetSnapshot`、`CompiledScene` 和完整 `FrameInput`。
2. 审计场景编译的隐藏状态、对象身份和不稳定遍历；先保证 CPU 产物可重放。
3. 从 `VulkanRenderer` 提取由完整输入驱动的生产帧记录器，保留 Minecraft 与呈现为外层。
4. 将 `WavefrontSignals` 的 raw 输出与 prepared reconstruction 输入拆成不同阶段类型；
   从 `NrdDenoiser` 分离输入准备、后端执行和合成。
5. 显式化 RNG、frame/history 状态与提交转移，清除队列顺序依赖和未定义 GPU 写入。
6. 增加阶段捕获、内容哈希与 replay 序列化，再建立低分辨率真实场景语义测试。

第一轮重构只改变边界、状态表达和可测试性，不主动改变积分器、采样分布、方差、偏差或
生产资源预算。任何物理图像拆分和新增稳态副本都需要单独的性能依据。

## 待审阅决策

- replay 的长期文件格式、兼容策略和是否提交二进制 fixture；
- Minecraft 必需叠层面的确定表示与等距命中处理；
- 闭源 DLSS RR 输出是否纳入严格同平台 bitwise 门禁；
- 真实光追语义测试的本地命令、专用硬件 CI 和执行频率。
