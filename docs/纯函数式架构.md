# 架构与数据流

Prime 采用函数式核心、命令式外壳。Minecraft、Vulkan、原生库、配置和文件 I/O 位于边界；
场景翻译、帧计划、历史判定、codec 和数学计算使用显式不可变输入。正确性和外部契约优先，
架构边界不得以额外 GPU pass、同步点或高频完整复制为代价。

## 依赖方向

```text
client / mixin / config
          ↓
     render.runtime
          ↓
     render.vulkan
          ↓
render / render.post / render.terrain / render.scene
```

Minecraft 捕获是侧向适配器：它把外部对象转换为 Prime 值，底层不反向依赖 client、mixin、
config 或 runtime。

`verifyArchitecture` 基于编译 class 和 `jdeps` 检查禁止依赖与跨层强连通分量，并由
`check` 强制执行。

## 生命周期所有者

| 层 | 当前职责 |
| --- | --- |
| `client` / `mixin` / `config` | 捕获 Minecraft 状态和每帧 `RendererSettings`，处理 UI 与组合根 |
| `render.runtime` | 渲染生命周期、模式、会话、诊断和 Minecraft terrain 所有权 |
| `render.runtime.terrain` | 异步流送、desired/current 状态、资源 epoch lease 与取消重排 |
| `render.vulkan` | context、帧执行、提交、native 后端和 GPU 资源生命周期 |
| `render.vulkan.terrain` | resident cluster、staging、BLAS/TLAS 与 compaction |
| `render` / `post` / `terrain` / `scene` | 不可变值、计划和纯算法 |

客户端线程单一拥有 runtime 控制器。GPU 句柄属于 Vulkan 执行边界；函数式核心只观察稳定
ID、revision 和描述值。唯一跨线程资源协调器是无锁 `ResourceEpochCoordinator`：捕获和 worker
只在外部 Minecraft 资源可用的 generation 上持有短 lease，retire 后拒绝新读取，最后一个
reader 退出时完成 reload future。

## 显式数据流

```text
Minecraft / 配置 / 输入
        ↓ 捕获并校验
Prime 不可变快照
        ↓
纯场景翻译与帧计划
        ↓
Vulkan / native 执行
        ↓ host 接受或 abandon
已提交历史与资源状态
```

每帧只使用 `beginFrame` 捕获的一份 `RendererSettings`。场景资源使用单调 revision；sprite
语义使用 `SpriteId` 和 `CapturedSprite`，不使用 Java 对象身份。数组可通过所有权转移零拷贝
发布，但发布后不得再由构建者修改。

## 提交与失败契约

帧状态遵循 prepare/accept：

1. 已提交状态与当前快照产生不可变计划；
2. 执行器记录命令和候选状态；
3. `encoder.execute()` 正常返回表示命令与资源所有权已被 Minecraft host submission 接受，
   此时才推进 Prime history；
4. execute 前失败执行 abandon，不推进状态；execute 后宿主失败则 runtime 进入 `FAILED` 并
   退休 renderer，不复用已推进历史。

这里不增加 GPU wait 或 queue-completion CPU 同步。每类 frame index、相机历史、图像初始化
和一次性上传状态只有一个生命周期所有者。

## 确定性边界

- 随机样本由稳定的像素、样本、路径槽、bounce、分支和 seed 寻址；
- 排序、哈希和序列化不得包含对象身份、GPU 地址、padding 或未初始化数据；
- 完全重合 primitive 的 traversal 命中顺序不是契约，需保留的叠层必须在场景构建阶段消歧；
- 逐 bit 复现只在平台、驱动、Shader、原生库、资源和配置一致时成立；
- NRD、DLSS、FSR、Vulkan traversal 和动态 mod 回调是外部边界，不伪装成 Prime 可重放状态。

## 变更检查

新增模块或状态前确认：

1. 副作用是否集中在 client、runtime 或 Vulkan 边界；
2. 影响结果的 Prime 状态是否都是显式输入且在计算期间不可变；
3. 状态是否由唯一所有者在 host 接受后更新；
4. 是否引入隐藏对象身份、不稳定顺序、跨层反向依赖或新的共享可变状态；
5. 是否增加稳态副本、GPU pass、同步或热路径分配；
6. 风险能否由行为测试、真实 Shader 测试、ABI 检查或架构门禁覆盖。
