# 区块簇场景翻译架构

## 状态

本文描述已经落地的首版架构。生产主路径为：

```text
VanillaSectionCapture
  → CapturedSectionGeometry
  → CapturedCluster（固定 64 槽位）
  → ClusterSceneTranslator
  → CpuClusterMesh
  → TerrainScene
```

`TerrainStreamer` 必须先收齐一个 cluster 中所有非空 Section 的捕获值，才允许调用唯一
翻译入口。`SectionMeshAccumulator`、`SectionClusterMeshBuilder` 和材质/OMM/灯光 builder
仍作为该调用独占的内部 lowering 阶段复用，不再由捕获边界或调度器直接驱动。

本文服从[纯函数式架构](纯函数式架构.md)的既有约定。这里的“纯转换”指观察意义上的纯度：
相同显式输入在约定平台和二进制下产生相同输出或相同失败。转换内部允许局部 builder、
arena、scratch、排序、原地写入和所有权转移；不要求捕获边界内部可重放，也不为形式上的
不可变引入完整世界副本或显著热路径成本。

## 目标

首版已经建立一个以 4×4×4 Section virtual cluster 为粒度的集中场景翻译层：

- Minecraft、Fabric renderer 和其他 mod 的捕获只记录实际接受的原始几何与语义事实；
- 一个 cluster 的 64 个 Section 捕获结果完整交给同一次翻译；
- layer 分类、已知静态叠层关系、材质翻译、宏面合并、体素建模、OMM、灯光和 ABI 打包
  在 cluster 翻译中集中决定；
- 转换层不查询 Minecraft、活动资源、GPU 或其他隐藏状态；
- 捕获结果可以直接进入转换测试和 `CompiledClusterCodec` 全链路回归；
- Vulkan 上传继续只消费最终 `CpuClusterMesh`，不认识方块、模型、sprite 或 mod API。

该设计解决当前 mesh 问题的共同结构原因：单个 quad 在 Section 捕获期间被过早偏移、
三角化、分类或丢失来源关系，cluster 阶段只能根据已经修改过的几何反推叠层、宿主面和
独立交叉面。

## 非目标

- 不替代 Minecraft 的模型选择、随机化、面剔除、流体 tessellation 或 Fabric renderer；
- 不冻结完整 `ClientLevel`、biome、light engine、模型系统或任意 mod 内部状态；
- 不要求捕获边界本身成为纯函数；
- 不以离线重建完整世界为目标，也不默认长期保存所有捕获数据；
- 不在本次重构中改变 Vulkan buffer、BLAS/TLAS、timeline 或 resident generation 契约；
- 不保证任意未知 mod 几何都能获得专用优化；无法证明的内容必须保守回退而不是猜测。

## 核心决策

### 捕获保存事实，不生成 Prime mesh

捕获层继续运行真正的 Minecraft `SectionCompiler`，并观察原版、Fabric 和流体路径实际接受的
quad。它可以执行 tint、collision、tag、sprite 和 render-layer 等必要外部查询，但不得：

- 为光线遍历添加几何偏移；
- 把 quad 提前拆成 Prime 三角形；
- 判断 `MergeFace`；
- 合并矩形；
- 生成纹理体素面；
- 合成材质叠层；
- 生成 OMM、emitter 或最终 primitive flags；
- 根据具体方块直接选择 Prime 的最终几何策略。

外部查询结果只要会影响后续翻译，就作为捕获事实固定下来。捕获可以保留 Minecraft 对象作为
边界内部的临时工作状态，但发布给转换层的值不得以对象身份、可变对象内容或集合迭代顺序作为
语义。

### 翻译粒度固定为 virtual cluster

一个翻译调用接收固定 64 个 Section 槽位。空 Section 以空值表示，而不是改变槽位编号。
Section 的捕获完成顺序和 worker 调度不得影响结果。

cluster 粒度提供以下必要上下文：

- 识别跨 Section 边界连续的面；
- 在同一方块或同一支撑平面内恢复叠层关系；
- 对宏面、体素 mesh 和材质组合执行稳定去重；
- 在最终几何确定后统一生成 OMM、灯光索引和 primitive 顺序；
- 以一个 generation 原子发布全部 64 个 Section 的结果。

cluster 以外的面不参与本次翻译。需要邻域状态的原版模型选择和 culling 仍由带 halo 的
`RenderSectionRegion` 在捕获边界完成。

### 集中表示为管线，不集中成巨型类

“集中”表示只有一个 cluster 翻译入口和一套最终决策，不要求所有算法位于同一个类。目标结构
是若干观察上纯、通过显式值连接的阶段；阶段之间可以借用同一调用拥有的可变 scratch。

## 总体数据流

```text
ClientLevel / model system / Fabric renderer / resources
  → 命令式捕获边界
  → CapturedCluster（64 个固定 Section 槽位）
  + MaterialSnapshot
  + ClusterTranslationSettings
  → ClusterTranslator
      1. validate
      2. canonicalize
      3. build surface graph
      4. resolve layers and materials
      5. lower geometry
      6. build OMM and emitters
      7. pack ABI
  → CpuClusterMesh
  → TerrainScene / staging / OMM / BLAS / TLAS
```

调度用的 world epoch、request generation、优先级和取消状态仍由 `TerrainStreamer` 所有。
它们决定结果是否可以提交，但不改变相同捕获内容的翻译结果，因此不进入几何语义。

## 输入契约

### `CapturedCluster`

概念结构如下，具体 Java 表示可以为紧凑 primitive 数组而不是对象树：

```text
CapturedCluster
  cluster origin
  section[64]
```

不变量：

- cluster origin 按四个 Section 对齐；
- 每个非空 Section 位于唯一固定槽位；
- 每个 Section 值及其 quad 列表发布后不可变；
- Section 捕获完成顺序不参与槽位编号或输出顺序；
- sprite 引用属于同一次显式传入的资源 epoch。

### `CapturedSection`

```text
CapturedSection
  accepted quad stream
```

Section 坐标由固定 cluster 槽位唯一确定，不在每个值中重复保存。`accepted quad stream`
保存原版编译器实际接受的 quad。捕获器在发布前把记录数与 `SectionCompiler.Results` 的最终
quad 数比较；计数只服务边界校验，不作为转换语义重复存入发布值。

空 Section 可以完全省略数据数组，但逻辑槽位必须保留。

### `CapturedQuad`

首版每个 quad 保存以下实际使用的事实：

```text
positions[4]
captured UVs[4]
declared face normal
resolved per-vertex color[4]
captured layer（opaque/cutout/translucent）
alpha-cut override
collision-empty fact
animation fact
emission fact
water / foliage / merge capability
raster-overlay role
sprite in the captured resource epoch
optional fluid facts
```

说明：

- positions 和 UV 在捕获层不得为了 Prime 的最终表示进行偏移或矩形化；
- Fabric 的四个顶点颜色必须原样保存，不能在捕获层提前平均；
- tint 查询位于边界，发布值只保存转换实际消费的最终四顶点颜色；
- `raster-overlay` 当前只标识原版草方块侧面和红石的栅格叠层角色，不通过几何偏移模拟
  draw order；
- `FluidFacts` 保存 owner 的 Section-local 坐标、顶面完整碰撞事实和六方向完整碰撞 bit
  mask。正反面折叠、补缝和贴实面抑制均在翻译层执行；
- 不保存当前转换不消费的完整 `BlockState`、mod 名、来源枚举、tint index 或 owner 对象。

首版直接保存 atlas UV 和 `TextureAtlasSprite` 引用。sprite 对象只作为显式资源 epoch 的
不可变内容句柄使用，去重与材质相等性使用资源标识和数值内容，不使用对象身份。未来若引入
脱离 Minecraft 资源生命周期的离线 fixture，再把该边界替换为稳定 material ID；本次不为
形式上的边界洁净复制完整 atlas。

### `MaterialSnapshot`

首版没有额外复制一个同名大对象；显式材质输入由捕获 quad 的 sprite 和不可变
`LabPbrMaterialSet` 共同组成。前者固定基础色/alpha、动画布局和 atlas rect，后者按资源标识
提供已经由材质边界解码的 normal、specular、height、emission 与逐 texel 规范化数据。
二者属于同一个资源重载 epoch，并提供当前翻译实际需要的：

- 基础色和 alpha 帧；
- 动画帧布局及采样事实；
- LabPBR normal、specular、height 和 emission；
- 基础纹理与辅助纹理的分辨率映射；
- atlas rect、padding 和 mip 契约，供仍需运行时采样的材质使用；
- 内容标识。

材质解码、LabPBR 规范化及混合分辨率映射属于材质抽象层。cluster 翻译只消费规范化结果，
不重新解释资源包格式。

该显式输入不要求复制完整 Minecraft atlas。需要烘焙的 CPU texel、动画信息和
运行时采样布局应按实际用途保留，并纳入高分辨率材质的内存与构建成本测量。

### `ClusterTranslationSettings`

所有影响结果的 Prime 配置和设备能力必须显式输入，例如：

- 是否启用纹理体素表面；
- 体素突起强度；
- OMM 是否可用及最大 subdivision；
- segment 工作集目标；
- 明确版本化的几何兼容策略。

玩家位置不直接进入翻译。`TerrainStreamer` 根据窗口位置决定某个 cluster 是否启用体素表面，
然后把这个布尔结果作为设置传入。

## 转换阶段

### 1. 校验与规范坐标

`CapturedCluster.Builder` 校验 cluster 对齐、Section 归属和重复槽位；
`SectionMeshAccumulator` 在 lowering 前校验全部 quad 属性有限。捕获计数在
`VanillaSectionCapture.finish` 发布 Section 值之前校验。Section-local 到 cluster-local
的平移只发生在翻译入口内部。

这一阶段不修复非法输入。现实可达的捕获契约失败应明确失败并保留来源信息；不能静默删除 quad
或伪造默认材质。

### 2. 解析 surface 角色

首版不创建宽泛的通用 surface-graph 对象。它只实现已有行为能够证明的关系：

- 同一精确单位平面上的 opaque 基础面；
- 捕获边界明确标记为 `rasterOverlay` 的静态 alpha-cut 覆盖面；
- raw fluid quad 及其 owner-local/collision facts；
- 其余内容的独立或保守逐 quad 路径。

基础层与覆盖层必须同时满足位置、朝向、单位范围、静态材质和显式角色约束才会组合。普通
同平面 cutout 不会仅凭几何重合被当成覆盖层。完全重合 primitive 的 traversal 顺序不是关系
依据。

### 3. 解析叠层与材质

静态、同宿主、同朝向且覆盖关系可证明的材质层可以逐 texel 合成。草方块侧面的基础层和染色
覆盖层属于这一类：

- alpha 在构建时裁决；
- 未覆盖 texel 使用基础层材质；
- 覆盖 texel 使用覆盖层材质和 tint；
- 最终只生成一个物理表面；
- 不保留重合实例，也不引入人为法线偏移。

以下内容当前不会自动套用静态叠层合成：

- 动画材质；
- 火焰等独立或附着内容；
- 草丛、花盘等交叉 card；
- 透射或体积边界；
- 无法证明层次和宿主关系的 mod quad。

这些内容保留独立或 conservative fallback。未来 attachment 关系必须增加新的必要捕获事实与
测试，不能根据基础色、方块名称或微小几何距离猜测层次。

### 4. 几何 lowering

在 surface graph 和最终材质已经确定后选择几何表示：

- 普通原始 quad 三角化；
- 可证明等价的矩形宏面；
- 纹理生成的体素高度面；
- alpha-tested cutout；
- thin-walled 或体积透射边界；
- 保守的逐 quad 回退。

几何 lowering 必须保持以下不变量：

- 不因优化改变覆盖、tint、动画、emission 或介质拓扑；
- 向外突起只由显式体素策略产生；
- 宏面或实例去重不依赖 Java 对象身份；
- 不支持的 mod mesh 保留原始形状和材质语义；
- fluid 的栅格反向重复面和明确启用策略后贴实完整碰撞体的面是有定义的表示转换；
  `FluidRenderer` 首个 authored outward quad 的绕序是介质边界与 emitter 朝向的唯一
  依据，不得再根据面中心相对 owner 中心的位置猜测；其他输入不得静默丢失。

### 5. OMM、灯光与 ABI 打包

OMM、emitter 和最终 primitive flags 必须根据 lowering 后的真实几何生成。它们不能在叠层合成或
体素建模之前绑定到旧三角形。

最终输出继续满足：

```text
CpuClusterMesh
  ordinary bounded segments
  opacity micromap
  compiled lights
  reusable voxel meshes
  voxel instances
```

普通 segments 可以有任意数量，但语义上仍属于一个 cluster base BLAS。实验性体素 mesh 的额外
BLAS/TLAS instance 数由显式几何策略决定。

## 纯度、状态与失败

转换层的公开契约是：

```text
translate(CapturedCluster, MaterialSnapshot, ClusterTranslationSettings)
  → CpuClusterMesh 或明确失败
```

要求：

1. 相同输入产生相同 primitive 顺序、内容和失败分类；
2. 不读取 Minecraft 单例、活动 atlas、时钟、玩家状态、GPU handle 或共享可变缓存；
3. 不修改发布后的输入；
4. 局部可变 scratch 不逃逸，不影响下一次调用；
5. 失败不发布半成品，也不推进 generation；
6. 哈希、排序和去重不使用对象身份或未定义集合顺序；
7. 调试诊断不得反过来改变翻译结果。

允许：

- 调用内部 builder 和原地写入；
- 本次调用拥有的 arena、scratch 和索引表；
- 所有权转移后的零拷贝只读数组；
- 不改变结果且所有输入键完整的缓存；首版不引入新的共享可变缓存或锁域。

`TerrainStreamer` 继续负责 request/in-flight/ready 状态机和 generation 校验。`TerrainScene`
继续使用 prepare/commit：只有 GPU 提交被接受后才发布新的 resident scene。

## 所有权与线程

建议所有权顺序：

```text
render thread
  创建 Minecraft/资源边界快照
worker
  捕获 64 个 Section
  独占 CapturedCluster builder
  发布 CapturedCluster
  独占运行 ClusterTranslator
  将数组所有权转移给 CpuClusterMesh
render thread
  只读借用 CpuClusterMesh 写入 staging
  GPU 提交成功后安排 CPU/GPU 资源退休
```

一个 cluster 的转换由一个 worker 独占，不引入跨 worker 共享 builder。64 个 Section 可以按固定
槽位逐个捕获；即使未来并行捕获，发布前也必须按槽位和 source sequence 形成稳定输入。

## 内存与性能

首版不设硬性捕获内存预算，正确性、完整性和可测性优先。当前
`CapturedSectionGeometry` 使用不可变 quad 对象与复制后的固定四顶点数组；一个 worker 独占
一个 cluster builder，翻译完成后捕获值不进入 resident 生命周期。大型最终输出仍使用有界
segment。

后续优化必须先测量，而不能重新把转换决策推回捕获边界：

- 评估 cluster-owned primitive arrays 或 struct-of-arrays；
- 用紧凑 ID 替换已证明占主导的重复资源引用；
- 阶段间以索引和范围共享 positions、UV 与颜色；
- 不为了测试在正常路径序列化捕获、复制整个 cluster 或执行 GPU readback；
- 高分辨率纹理测量 CPU texel、体素三角形、BLAS 和 staging 的平方级增长。

若原始捕获与最终 mesh 的同时驻留成为主要峰值，应优先评估 arena 复用、紧凑编码和阶段内所有权
转移；不得以增加 TLAS instance 或静默丢弃几何换取较低内存。

## 测试策略

### 捕获边界契约测试

使用真实 Minecraft/Fabric 编译路径验证：

- 原版最终 quad 数等于捕获数；
- vanilla、Fabric 和 fluid quad 的位置、UV、颜色、材质、来源和顺序完整；
- 捕获层没有 Prime 专用几何偏移；
- 外部查询结果在发布后固定；
- 非法或未支持 atlas 来源明确失败。

这些是边界集成测试，不要求 Minecraft 内部可重放。

### 纯转换测试

直接构造 `CapturedCluster` 和 `MaterialSnapshot`，覆盖：

- 普通立方体、非完整模型和跨 Section 面；
- 草方块静态基础层与染色覆盖层；
- 草丛、向日葵花盘等独立交叉面；
- 发光地衣、火焰等 attachment；
- 动画、cutout、透射、水和 foliage；
- LabPBR 缺省、混合分辨率和 SPBR 兼容输入；
- mod 生成的旋转、非矩形、多 tint 和非方块 atlas quad；
- OMM、emitter index、primitive ABI 和缓存 round-trip。

测试观察输出几何、覆盖、材质、灯光和公开 ABI，不通过搜索源码或函数名证明行为。

### 全链路 fixture

选择少量稳定且重要的真实捕获结果，验证：

```text
CapturedCluster
  → ClusterTranslator
  → CpuClusterMesh
  → CompiledClusterCodec round-trip
```

fixture 只包含进入 Prime 函数式核心所需的显式输入，不尝试冻结完整 Minecraft 世界。默认运行不
保存所有 cluster；只有经过确认的长期回归案例进入版本库。

### 确定性与性质

- 重复翻译相同输入产生相同 fingerprint；
- Section 捕获完成顺序变化不改变结果；
- 合法 quad 的 disposition 总数等于输入总数；
- 完全重合层不会把 traversal 命中顺序暴露为语义；
- 关闭优化时所有内容都有保守逐 quad 表示；
- 任意失败都不产生可上传的部分 generation。

## 落地状态

### 阶段 1：引入原始捕获值（完成）

- 新增紧凑 `CapturedSection`/`CapturedCluster`；
- 让 vanilla、Fabric 和 fluid Mixins 只写捕获事实；
- 保留 quad 数完整性检查；
- 建立捕获边界集成测试；
- 捕获后不生成 Prime mesh。

### 阶段 2：建立 cluster translator 基线（完成）

- 新增唯一 `ClusterTranslator` 入口；
- `TerrainStreamer` 只构造 `CapturedCluster` 并调用唯一翻译入口；
- 旧 builder 作为翻译调用内部的 lowering 组件复用；
- 普通几何、分类、灯光、OMM、ABI、宏面和体素表面均在该入口之后产生。

### 阶段 3：迁移集中决策（首版完成）

已经迁移：

1. layer classification 和 fluid representation conversion；
2. 显式 `rasterOverlay` 静态层组合；
3. 材质翻译与 alpha 解析；
4. 宏面合并；
5. 体素表面与材质烘焙；
6. OMM、emitter 和 conservative fallback。

捕获层只固定后续必需的外部查询结果，不再拥有以上最终决策。

### 阶段 4：删除旧生产路径（完成）

- 删除捕获阶段的 overlay offset 和方块专用 Prime mesh 修正；
- 调度器不再逐 Section 构造 `CpuSectionGeometry`；
- `TerrainScene` 只接受 cluster translator 的最终 `CpuClusterMesh`；
- `SectionMeshAccumulator` 与 `SectionClusterMeshBuilder` 仅是翻译函数的局部内部组件。

## 后续维护重点

1. 新 mesh 语义需要额外事实时，只增加被转换实际消费的字段；
2. 草丛、花盘、火焰和发光地衣仍需 attachment/independent-card 契约；
3. atlas sprite 引用若妨碍离线 fixture，再以稳定 material ID 替换，不复制无关资源；
4. 高分辨率材质和高视距下先测量捕获峰值与吞吐，再决定紧凑表示；
5. 不引入共享可变翻译缓存或新锁域；必要时须另行审查所有权与失效协议。
