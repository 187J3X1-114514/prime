# 纹理翻译架构

Prime 把 Minecraft atlas、独立纹理、LabPBR 文件和动画状态视为输入格式，不允许这些来源的
坐标、对象或命名进入生产材质链。纹理与 mesh 一样必须在资源边界翻译为 Prime 自有 IR：

```text
Minecraft TextureAtlasSprite / 独立纹理 / LabPBR
  → TextureSource（资源 generation 内借用）
  → TextureCatalog（TextureId、逻辑尺寸、通道与动画事实）
  → TextureRecord + sprite-local UV
  → generation-owned compact page set（分页物理存储）
  → 生产 material adapter
```

## 规范身份与坐标

`TextureId` 是 renderer 生命周期内稳定的 24-bit 非零整数。初次出现时按稳定资源身份单调分配；
资源暂时消失也不回收 ID，同一 `SpriteId` 以后重新出现仍使用原 ID。renderer 销毁会同时销毁
所有引用它的 mesh 和 record，之后才允许从头建立新注册表。零是“无静态纹理”哨兵，不得进入
静态采样；Minecraft 的 missing sprite 也取得正常非零 ID。达到上限必须明确失败，不能复用、
截断或哈希碰撞。捕获边界以 `SpriteId` 或显式外部纹理身份解析一次，
worker、terrain、light、OMM 和 shader 不再执行字符串或 atlas 位置查找。
当前 generation 的 record 表允许为暂时消失的 ID 保留零值空洞，但不保留已经不属于当前资源
集合的 page 像素；这属于资源真实删除，不是按预算或可见性裁剪。

静态纹理图元保存 `TextureId` 和 sprite-local UV。局部坐标以逻辑帧的左上、右下分别为
`(0, 0)`、`(1, 1)`。当前静态地形只接受规范化局部坐标；需要 repeat 或非标准子区域的来源必须
在适配边界显式降低，不能隐式越界采样相邻纹理。Minecraft atlas UV
只能在 `render.scene.vanilla` 中用于识别 sprite 并转换为局部坐标；不得写入 `CpuClusterMesh`、
`PrimitiveRecord`、light emitter 或生产 shader。

`TextureRecord` 只描述规范逻辑纹理，不暴露来源对象：

- albedo 在已有 Minecraft backing 中的内容矩形；
- normal 和 optical 各自的 page index 与内容矩形；
- 逻辑 frame 宽高、各通道最大 mip，以及用无效 page index 编码的通道 availability；
- 缺失资源与尚未常驻是不同状态。只有资源确实缺失时才允许规范 fallback。

物理矩形变化只更新 texture record，不改变 `TextureId`、mesh 或材质语义。LOD 由局部 UV 密度
和逻辑 frame 尺寸计算，不依赖 backing page 尺寸。

## 源格式翻译

LabPBR 只存在于资源适配层。进入 catalog 前转换为 Prime 规范通道：

- normal：切线空间平均方向与从法线分布反演的 perceptual roughness；
- optical：roughness、Fresnel、subsurface/porosity 与 emission；
- height：只供 CPU 几何位移消费，不进入运行时 normal 通道；
- coverage、emission distribution、OMM 和位移数据由同一 source 一次派生。

source 由资源 generation 单一拥有，GPU 上传缓冲在首次提交后退休。CPU OMM、emission、height
和体素材质确实需要的派生数据可以随 generation 保留，但禁止为相同用途重复克隆完整 RGBA
数组。按 cluster 常驻落地前不能提前释放仍可能被 worker 消费的 source。

## 分页物理存储

纹理数量不决定常驻显存；实际使用的带 mip 纹素面积才决定。禁止以下布局：

- 与 Minecraft atlas 等尺寸的 normal/optical 镜像；
- 以最大纹理尺寸统一分配的 array layer；
- 每个逻辑纹理一个 VkImage 或 descriptor；
- 在资源 reload 时全量解码并永久保留所有 source 像素。

albedo、normal 和 optical 按格式、sampler、mip、静态/动画分别进入矩形 page pool。页面使用
实际宽高分配；非正方形和 NPOT 纹理不得扩成方形。每个矩形包含 mip-safe gutter，并按自身
最大 mip 对齐。超出普通页面的合法纹理使用独立 backing；超过设备上限或预算必须明确报告。

逻辑纹理数与 descriptor 数解耦：数万个 `TextureId` 映射到有限的 page descriptor。record
使用 page index 选择 backing，unused descriptor 绑定不可观察的 dummy image。物理 page 数受
设备 descriptor 上限和纹理预算共同约束。

## 当前常驻与所有权

当前基线在每个资源 generation 发布前建立并上传全 catalog 的 compact normal/optical page
set；albedo 通过 texture record 把 Minecraft 已有 atlas 作为只读 external backing 引入，不创建
第二份 albedo 镜像。它消除了按 atlas 外接矩形付费的主要内存问题，常驻字节改为实际辅助纹理
矩形及 mip 面积。纹理是否已被可见 cluster 使用不影响捕获、上传或常驻状态。

页面、record、动画更新和 reload 替换都由 render thread 单一拥有。worker 只读取 generation
固定的 catalog；不得增加共享锁、跨线程 page 分配或隐藏的引用计数修改。页面建立失败必须在
发布新 generation 前失败，不能让 mesh 看见缺页 record。

renderer 在无世界的 ready 阶段完成全 catalog 捕获、页面构建和初次 GPU 上传；资源 reload 的
apply 同样在恢复 terrain worker epoch 前完成替换上传。正常游戏帧只允许提交真实动画帧变化，
不得承担静态 catalog、record 或页面的首次准备。

超大资源包只能优化无损压缩、矩形 packing、mip 生成、上传批次、重复派生数据和临时缓冲生命
周期；不得根据当前可见性、引用计数、加载顺序或经验预算主动裁剪、驱逐或延迟 catalog 中的
合法纹理。超过明确的设备上限或硬预算必须在发布前报告，不能以运行时 fallback 伪造完整性。

## ABI 与 shader 边界

`PrimitiveRecord` 保持 32 bytes。静态普通图元复用 `flagsEmitter[3..26]` 保存 `TextureId`；
发光图元保留 emitter index，并在 `LightEmitter.metadata.w` 保存其 `TextureId`；动态外部纹理
保留显式 tagged payload。raster composite 不得继续占用该 payload 保存 overlay tint，统一
降低为已有 surface-relation sidecar。

生产 shader 只导入窄纹理能力。当前 normal 与 optical 的消费者集合相同，因此合并为一个
auxiliary access 模块；若消费者集合分化，必须按实际依赖再次切开：

- albedo/coverage 只加载 header 与 albedo rect；
- normal 只在资源存在且全局模式为资源法线时加载 normal rect；
- optical/emission 只在对应通道存在时加载 optical rect；
- 不得把完整 texture record 留在路径状态或长期寄存器中；
- 不得导入 Minecraft、LabPBR source 或诊断模块。

`TextureId` 查表是静态纹理路径唯一允许的地址间接层。实现必须使用 SoA 或等价窄加载，避免
无 normal/optical 的命中承担其记录带宽。动态独立纹理是明确的 external backing，不得借用
静态 `TextureId` 猜测生命周期。

## 动画、reload 与离线冻结

一个 animation slot 同步驱动同一逻辑纹理的 albedo、normal 和 optical。GPU 只为当前输出帧
保留矩形，不能把纵向/横向完整 sprite sheet 当作常驻区域。动画更新只触碰动画页面，不转换
大型静态页面。

catalog、layout 和 record 带资源 generation，而 `TextureId` 不随 generation 重编号。编译结果
和上传事务必须匹配当前 generation；旧结果直接取消。完整新 page set 和 record 上传就绪后才
能发布。normal/optical 像素内容变化只替换页面；availability、emission、`TextureId` 或启用
几何位移时的 height/material 变化才失效 terrain 翻译。移除 resident primitive 已声明使用的
页面通道时，旧 primitive 必须先退出场景，不能使用新 record 中的 absent page。离线会话冻结
texture generation、record 和动画内容；任一资源 generation 变化都退出会话。

## 验收

- 行为：atlas 子区域、repeat/clamp、NPOT、细长纹理、不同尺寸、overlay/bilateral/boundary、
  动画插值、OMM、emission、位移与动态外部纹理保持一致；
- ABI：`PrimitiveRecord` 仍为 32 bytes，普通、emitter、dynamic payload 穷举往返；
- 身份：新增、移除和重新加入纹理不得改变任何既有 `SpriteId` 的 `TextureId`，退休 ID 不复用；
- 生命周期：未完成的新 page set 不发布，取消与 reload 不泄漏资源，旧 page 延迟退休；
- 内存：上传缓冲在首次提交后退休，normal/optical 常驻字节按实际
  矩形统计，不得按 Minecraft atlas 面积分配，也不得按可见性主动裁剪 catalog；
- GPU：固定场景配对测量，frame/transport time 的 95% 置信上界不得高于基线；不能用内存或
  构建收益抵偿帧性能回退；
- 架构：`render.terrain`、Vulkan page owner 和生产 shader 不得引用 Minecraft texture 类型、
  `TextureAtlasSprite`、LabPBR source frame 或 atlas UV。
