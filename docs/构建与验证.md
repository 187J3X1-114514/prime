# 构建与验证

## 环境

- JDK 25（当前验证补丁版 25.0.4）；
- Vulkan SDK 1.4.357；
- SDK 中可用的 `spirv-val`、`spirv-dis` 与独立 Slang 2026.14.1 `slangc`。

Windows PowerShell 示例：

```powershell
$env:JAVA_HOME = 'C:\WorkSpace\_tools\temurin-25.0.4\jdk-25.0.4+7'
$env:VULKAN_SDK = 'C:\VulkanSDK\1.4.357.0'
$env:PRIME_SLANG = 'C:\WorkSpace\_tools\slang-2026.14.1'
$env:Path = "$env:JAVA_HOME\bin;$env:VULKAN_SDK\Bin;$env:PRIME_SLANG\bin;$env:Path"
.\gradlew.bat build --console=plain `
  -PprimeSlangCompiler="$env:PRIME_SLANG\bin\slangc.exe"
```

`build` 编译 Java 和生产 Shader、运行 CPU 测试，并检查架构边界、Shader include 图、
RoboCute 参考一致性、Slang 工具链、ABI 和发行 JAR。它不执行需要 Vulkan 设备的
`shaderTest`。

`slangc` 默认从 `VULKAN_SDK` 或 `PATH` 解析。使用独立的官方 Slang 发行包时，通过
`-PprimeSlangCompiler=<path>` 显式指定；编译器仍必须与 `primeSlangVersion` 完全一致。

## 开发运行

```powershell
.\gradlew.bat runClient
```

默认开发配置使用 Vulkan 并启用 validation。验证 OpenGL 下 Prime 不接管渲染：

```powershell
.\gradlew.bat runClient -PprimeBackend=opengl
```

不要使用 Gradle `--args` 覆盖图形后端；Loom 会将它与已有参数合并。

## 验证任务

常用门禁：

```powershell
# CPU 测试
.\gradlew.bat test --rerun-tasks --console=plain

# 完整非 GPU 构建与发行检查
.\gradlew.bat build --console=plain

# 在 Vulkan compute 设备上运行真实 Slang 属性测试
.\gradlew.bat shaderTest --console=plain
```

主要任务：

- `test`：Java、状态机、codec、ABI 和数学性质；
- `compileSlangShaders`：以 `-O2`、默认浮点模式、row-major/GL ABI 和直接 SPIR-V 后端编译
  全部生产 Shader，生成普通、subgroup queue 与 SER permutation，保留最小符号信息并运行
  `spirv-val`；
- `verifyShaderIncludeGraph`：检查 Shader include 图无环，报告位于
  `build/reports/prime-shaders/include-graph.txt`；
- `verifySlangToolchain`：核对固定 Slang 版本，编译最小 Vulkan 1.2/SPIR-V 1.5 Shader，
  并验证 descriptor、push constant 与矩阵布局基线；
- `verifyGeneratedSlangAbi`：从 `shaders/abi.json` 生成 Slang 类型后，在最终 SPIR-V 中逐字段
  验证 offset、storage-buffer stride、push constant 和矩阵装饰；
- `compileSlangTestShaders`：以默认浮点模式和直接 SPIR-V 后端编译 Slang 属性测试；
- `verifySlangRayPayloadAbi`：检查所有 ray-tracing stage 的 surface=0、shadow=1 payload location，
  并保证 SER 产物只使用标准 EXT invocation-reorder 方言；
- `verifyRoboCutePort`：核对受保护 RoboCute 移植与锁定参考；
- `verifyArchitecture`：对已编译 class 运行 `jdeps` 并检查包层、反向依赖和跨层 SCC，报告位于
  `build/reports/prime-architecture/`；
- `verifyDistributionJar`：检查发行 JAR 的资源、许可、Shader 和 Windows 原生库；
- `shaderTest`：在 Vulkan 设备上执行 Slang 数值、状态、分布、能量和 ABI 行为测试。

Windows x86-64 测试会实际加载 NRD、FidelityFX 和 DLSS RR 桥接库并验证 ABI。其他平台
跳过 Windows native 执行，但仍编译 Java/Shader 并检查 JAR。

## Shader 调试

生产 SPIR-V 默认使用 Slang `-g1` 保留栈与符号信息；非语义调试信息不改变执行结果。完整源码
行映射会显著放大大型 wavefront 的编译时间，需专项分析时再临时使用 `-g2`。验证当前产物：

```powershell
.\gradlew.bat compileSlangShaders --rerun-tasks -PprimeShaderFullDebug=true
```

## CI

GitHub Actions 在 Ubuntu 24.04、JDK 25、Vulkan SDK 1.4.357、Slang 2026.14.1 和 Mesa Lavapipe 上运行：

```text
clean build shaderTest
```

CI 保存失败测试报告并上传构建生成的 JAR。
