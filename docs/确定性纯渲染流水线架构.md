# 确定性纯渲染流水线架构（试行）

## 目的与边界

Prime 的长期方向是把渲染定义为显式输入到显式输出的确定性变换。对任一合法输入，
在相同平台、二进制和配置下，各阶段输出都应可逐 bit 重放；随机采样只扩大输入空间，
不允许制造不可复现的执行结果。

这里的“纯”是逻辑语义，不要求取消 GPU 资源、命令提交等必要副作用。副作用必须集中在
Minecraft 捕获、GPU 驻留和设备执行三个边界；场景编译、帧计划、积分器语义、重建输入
准备和历史转移不得读取隐藏状态。

本架构首先保证数据流、单位、坐标、资源身份、生命周期和重放正确性，不以验证 NRD、
FSR 或 DLSS 的降噪能力为目标，也不要求为测试牺牲生产性能。逻辑阶段可以在执行器中
安全地原地复用同一 GPU 图像。

## 已成为事实的基线

- `RayTracingRuntime` 是渲染接管和失败回退的唯一生命周期入口；Mixin 只负责 Minecraft
  接入和设备协商。
- `render/terrain` 已以 Section 快照为异步网格化输入，以 virtual cluster 为 BLAS、
  TLAS instance、灯光树叶、generation 和清退单位；新 generation 完整建立后才替换旧
  场景。
- `render/vulkan` 独占 Vulkan 句柄、VMA、同步、加速结构、descriptor、pipeline 和延迟
  退休。热路径不使用 `vkDeviceWaitIdle`，历史只在实际提交后推进。
- 实时与截图共用固定 12 轮、两个稳定路径槽和紧凑活动队列的 wavefront 主积分器。
  `PathState`、`SurfaceInteraction`、BSDF、PDF、采样维度和 reconstruction guide 已是
  显式契约；调度层不重解释积分器数学。
- `RawWavefrontFrame` 是积分器原始输出边界；NRD 只通过 `PreparedNrdFrame` 解析原生输入。
  `RealtimePostProcessor` 已显式拥有后端尺寸、jitter、record/submitted 生命周期和线性
  HDR 输出。
- `shaders/abi.json` 是 Java/GLSL 布局、工作色彩空间和关键常量的唯一声明源；RoboCute
  移植保持受保护的固定参考边界。
- GPU 属性测试已经用固定 seed 执行真实生产 GLSL，并要求失败输入可重放；当前主要覆盖
  数学片段，尚未覆盖真实积分器到重建输入的完整阶段语义。

当前 `VulkanRenderer` 仍承担 Minecraft 状态读取、资源选择、replay 序列编排和呈现；
实时、截图和 replay probe 的 Vulkan 命令编排已分别交给 `RealtimeFrameExecutor`、
`ScreenshotFrameExecutor` 与 `ReplayProbeFrameExecutor`。`NrdDenoiser` 仍集中拥有输入
准备、原生 dispatch 和合成的设备实现。完整 `MinecraftSnapshot` 与 NRD 子设备模块的
类级所有权尚未完全拆分，不应被文档误写为已完成。

## 试行进度

- `VanillaSectionSnapshot` 已把 Section 坐标与 Mojang 3×3×3 `SectionCopy` 区域组成
  显式方块状态快照；`VanillaAssetSnapshot` 固定同一 reload epoch 的模型、流体、颜色、
  sprite、LabPBR 与几何策略。`VanillaSceneInterpreter` 只保留可替换的缓冲池副作用。
  `SectionCopy` 已冻结方块状态和方块实体映射，但 `RenderSectionRegion` 的生物群系染色与
  光照引擎仍委托给 live `ClientLevel`，因此这一层尚不能称为完整
  `MinecraftSnapshot`。冻结 biome tint 需要新增主线程捕获成本，实施前先测量。
- `IntegratorFrameInput` 与确定性 ABI 编码器已从 `VulkanRenderer` 分离，同一输入会完整
  覆盖并逐 bit 生成相同 push constants；`RayTracingPipeline` 在唯一设备边界绑定
  `ResidentSceneView` 的地址并记录生产 wavefront。
- `RealtimeFrameInput` 一次捕获相机、时间、场景/纹理版本、尺寸、太阳、介质、模式、
  配置和诊断；`RealtimeFramePlan` 从样本与后端历史计划生成同一份积分/重建语义，并
  拒绝 reset 或 jitter 漂移。输入同时保存 render/display extent，并在申请后端帧前
  验证 mode、quality 和两组尺寸与实际 reconstruction backend 一致。原版 atlas 与
  LabPBR 的实际替换只产生单调 `textureRevision`，Vulkan view/sampler 句柄不再进入纯
  历史状态；逐帧纹理动画不会错误清空历史。
- 实时 Sobol 序列、NRD 历史以及 FSR/DLSS RR 的公共时序身份均采用纯
  `plan → submitted commit`；墙钟时间只在外层每帧捕获一次，未提交帧不再推进样本或
  历史。相机切变、场景/材质/光照版本变化和显式 reset 会一致传给全部重建后端。
- `ReconstructionFrameHistory` 统一拥有 FSR 与 DLSS RR 的公共 temporal identity；
  每个后端一次只允许一个未提交版本，recording 只能消费一次，显式 reset 不能与悬空
  版本竞争。native 设备类不再直接持有或覆盖已提交历史。
- `NrdFrameInput → NrdFramePlan` 已从命令录制中分离：history camera、当前/历史 jitter、
  frame index、reset 和 delta 在 `beginFrame` 或 replay 命令申请前确定；输入准备只消费
  一次性 planned token，原生 dispatch 和 Vulkan 失败不会重新规划或提交历史。
  replay v2 同时保存导致转移的 frame time、场景/纹理版本、force-reset 与
  native-validation 语义，而不只保存派生矩阵。
- `NrdFrameHistory` 是 NRD 逻辑历史的单一所有者，只允许一个未提交版本；设备执行器仅
  消费其一次性计划并返回已提交版本。`NrdDenoiser` 不再读取或推进隐藏时序状态，实时
  与 replay 各自拥有隔离的 history。
- `RealtimeFrameExecutor` 是实时帧申请命令缓冲、绑定驻留场景/资产、记录 wavefront 与
  reconstruction、拷贝、提交及后端 history commit 的设备副作用边界；
  `VulkanImageTransitions` 集中保存原先分散在 renderer 中的同一组 layout 与
  availability/visibility 契约。外层只在执行成功后提交 Sobol 与设置版本状态。
- `ScreenshotFrameInput → ScreenshotFramePlan` 在设备执行前固定 native ray cone、
  sample index/epoch、零 jitter、介质、scene/texture revision 和曝光；
  `ScreenshotFrameExecutor` 只消费该计划，成功提交后外层才递增 64 位样本计数。截图
  会冻结 atlas view/sampler 及其逻辑 texture revision；同一句柄下发生资产 epoch
  变化也会退出该统计序列，command recording 不再隐式读取随机状态或全局设置。
- `ReplayProbeFrameExecutor` 只消费已经固定的积分器输入、NRD planned token、平台与
  二进制指纹以及本帧驻留资源；probe 的资源准备、wavefront、捕获、提交与 history
  commit 已从 renderer 分离。`ReplayProbeController` 进一步独占请求、两套隔离历史、
  序列顺序、异步完成和资源清理；completion 不再跨线程写
  `VulkanRenderer` 的普通字段，交互 descriptor 在同一 render-thread 调用返回前恢复。
- CPU 编译结果已命名为 `CompiledCluster`，GPU 句柄视图已命名为 `ResidentSceneView`；
  可选 `CompiledClusterFingerprint` 以不含对象身份和设备地址的 canonical 内容生成
  SHA-256，未启用捕获时没有生产热路径成本。局部灯光数据采用可重定位编码，解码时
  校验 shader ABI、树拓扑和 emitter 引用。
- 可合并面的材质身份已由 Java 对象身份改为稳定资源名；UV、旋转、材质参数和 OMM
  策略仍参与精确比较，因此不扩大合并范围。
- world light tree 更新只接收严格按 cluster key 排序、无 Vulkan 句柄的
  `WorldLightTreeInput`；增量槽位、空闲顺序、SAH 基线和 CPU 树可按需捕获为不可变
  `CpuWorldLightTree.Snapshot`，并从该快照逐 bit 恢复下一次更新。快照复制为
  O(tree size)，只用于 replay/测试，不进入普通场景更新路径。
- raygen binding 12 已从误导性的 motion 语义改为 transport metadata；图像数量、格式、
  binding、dispatch 和 shader 算法均未改变。
- 显式低分辨率 probe 以生产 wavefront、`nrd_motion` 和原生 NRD 路径生成 restart 帧与
  固定 0.25 方块平移帧，在 raw resolve 后和 NRD dispatch 前回读稳定 signal schema；
  未请求时只保留一次空的原子请求检查，不创建资源或增加 GPU 命令。
- replay 已包含无设备地址的帧语义、NRD 历史输入、平台指纹、Prime 可执行代码及当前
  SPIR-V/native/静态 LUT 资源指纹、阶段数据、版本化序列编码、NRD 输入不变量检查和
  首个逐 bit 分歧定位。`Ctrl+Alt+F10` 会从同一交互帧捕获的场景、相机和 atlas 状态
  提交两套独立历史的 64×64 真实序列，并报告语义/bitwise 结果；通过后把 reference
  原子保存为 `run/prime/replay/last-success.prseq`。fixture 加载有 256 MiB 上限，必须
  通过版本头、SHA-256 完整性、容器解码和 NRD 帧/历史语义校验。
  `validateReplayFixture` 可离线校验一个文件，`compareReplayFixtures` 可在平台与二进制
  严格相同时定位两次捕获的首个逐 bit 分歧。
  这些文件当前记录真实输出，但尚不能脱离原场景重新执行 GPU；动态 block/LabPBR
  atlas、完整场景资产快照及无需进入游戏的自动启动入口仍待补齐。
- 当前 world light tree 保留增量叶槽和拓扑以降低场景更新成本；同一最终 cluster 集合
  经过不同增删历史，仍可能得到不同但无偏的采样拓扑。因此严格 replay 的输入是
  `WorldLightTreeInput + CpuWorldLightTree.Snapshot`，而不是仅有当前
  `CompiledScene`。快照的长期磁盘 codec 尚未确定。
- 原版 Section 的方块状态和方块实体映射已经复制，但 `RenderSectionRegion` 仍通过
  `ClientLevel` 查询 biome tint 与 light engine。即使关闭 AO，原版 flat lighter 仍会
  读取光照值；Prime 不消费该 raster light，但 Fabric 自定义 renderer 可能用它改变
  几何，因此不能以常量替代而自称兼容。两者都属于需要测量捕获成本后再冻结的明确边界。

## 目标数据流

```text
Minecraft live state
  └─ MinecraftCapture.read                         [副作用]
       → MinecraftSnapshot + AssetSnapshot
  └─ SceneCompiler.compile                         [纯函数]
       → CompiledScene
  └─ SceneUploader.upload                          [副作用]
       → ResidentScene

ResidentScene + FrameInput
  └─ Integrator.plan                               [纯计划]
       → RenderPlan
  └─ RenderDevice.execute                          [副作用]
       → RawWavefrontFrame
  └─ NrdInputPreparer.prepare                      [纯语义]
       → PreparedNrdFrame
  └─ ReconstructionBackend.execute                 [显式历史]
       → ReconstructedFrame + NextHistory
  └─ Composite/Display                             [纯语义 + 设备执行]
       → LinearFrame / DisplayFrame
```

`MinecraftSnapshot` 是对 live world、模型和资源状态的一次不可变捕获；读取 live 对象是
副作用，从快照开始的 mesh、面合并、旋转、材质、OMM、灯光列表和树构建必须只由输入
决定。`CompiledScene` 保存稳定排序的内容数据，不包含偶然的 Java 对象身份或 GPU 句柄。

`FrameInput` 至少显式包含相机及历史相机、场景与资产版本、尺寸、sample index/epoch、随机种子
或采样序列、jitter、太阳、相机介质、材质与灯光设置、重建模式和历史重置条件。系统
时间、全局单例、未提交帧和可变配置不得成为隐式输入。

阶段类型必须表达语义和生命周期：

```text
RawWavefrontFrame → PreparedNrdFrame → DenoisedFrame → CompositedFrame
```

物理执行器可以让这些逻辑版本别名到同一图像，但 API 不得允许 raw/prepared 混用、
重复准备或越过必要 barrier。历史同样采用 `HistoryInput → NextHistory`，且只有成功提交
后才能成为下一帧输入。

## 确定性契约

1. 随机状态由稳定的像素、样本、路径槽、bounce、分支和 seed 寻址，不依赖活动队列
   索引、atomic 返回顺序、线程调度或墙钟时间。
2. 场景编译中的集合遍历、primitive、instance、材质、纹理、OMM 和灯光顺序必须稳定。
   缓存只影响成本，不影响产物。
3. Shader 写入必须无数据竞争。跨 invocation 的浮点原子累加或无序归约需要改为单写者、
   固定归约树或与顺序无关的表示；队列顺序不得改变路径结果。
4. 同一合法 replay 在同一平台上重复执行时，各阶段内容哈希必须一致。平台指纹包括
   GPU/驱动、Vulkan 特性、SPIR-V、原生库、资源格式和特化配置。
5. 完全重合且等距的 primitive、未初始化资源和未定义同步不属于合法输入。Minecraft
   确实需要的叠层面必须由场景编译器给出确定表示，不能依赖硬件 traversal 的等距命中
   顺序。
6. 开放后端的显式永久池可作为历史值管理。闭源后端若不公开内部状态，严格契约止于
   输入、reset 和特定运行时的实测输出，不伪造可序列化保证。

## 副作用与所有权

- `MinecraftCapture`：唯一允许读取 live Minecraft 状态的边界，输出不可变且自洽的快照。
- `SceneUploader`：唯一把 `CompiledScene` 变为 GPU 驻留资源的边界；资源具有单一所有者，
  通过替换后提交和 timeline 完成点退休。
- `RenderDevice`：唯一创建临时资源、记录/提交命令和回读结果的边界。算法模块只产生
  输入验证、资源需求和 dispatch/trace 计划。
- reconstruction backend：历史所有权必须集中；录制中的 frame token 不得修改已提交
  历史，失败提交不得推进状态。

共享可变全局状态、跨阶段隐藏写入和以对象身份表示语义均不允许。性能所需的 descriptor
复用、图像别名和暂存池属于执行器内部优化，不能改变逻辑版本或可观察结果。

## 重放与语义测试

`RenderReplay` 应保存足以从选定边界独立执行的最小输入：

- 平台指纹以及 shader/native/resource 哈希；
- `MinecraftSnapshot` 或 `CompiledScene`；
- 一帧或一段 `FrameInput`；
- 显式历史输入和预期 reset；
- 失败阶段及必要的中间产物。

生产帧执行器提供可选捕获点，至少位于 wavefront resolve 后和 reconstruction dispatch
前。正常运行不分配 readback、不增加 dispatch；测试在低分辨率真实场景中运行生产
SceneCompiler、BLAS/TLAS、wavefront 和输入准备，再回读真实阶段输出。

当前本地入口：

```text
Ctrl+Alt+F10
  → 两套隔离历史的 64×64 生产渲染
  → 语义校验 + 同平台逐 bit 比较
  → run/prime/replay/last-success.prseq

gradlew validateReplayFixture -PprimeReplayFixture=<fixture>
gradlew compareReplayFixtures \
  -PprimeReplayExpected=<reference> -PprimeReplayActual=<actual>
```

fixture 的文件 I/O 只存在于显式调试/离线边界；保存先校验、写入同目录临时文件并强制
落盘，再原子替换（文件系统不支持时退化为完整临时文件替换），不进入生产帧热路径。

核心测试分为：

- 纯函数属性测试：快照编译、布局、状态转移、矩阵和输入适配；
- 真实渲染语义测试：position、normal、material、hitT、SH、view-Z、MV、主/反射/透明
  资源身份及 NaN/Inf；
- 确定性测试：同一 replay 多次执行并逐 bit 比较每个阶段，定位第一个分歧；
- 回归 replay：线上或目测问题缩小为固定输入后永久保留。

NRD 测试的权威观察点是生产积分器实际生成并即将绑定给 NRD 的图像，而非测试代码伪造
的理想输入。重点验证 `old = new + MV`、像素单位、view-Z 差、jitter、虚拟表面、材质
分类、resource identifier 和 history 提交语义；不把 NRD 的收敛速度作为主要门禁。

## 渐进式落地顺序

1. 定义不可变 `MinecraftSnapshot`、`AssetSnapshot`、`CompiledScene` 和完整 `FrameInput`。
2. 审计场景编译的隐藏状态、对象身份和不稳定遍历；先保证 CPU 产物可重放。
3. 从 `VulkanRenderer` 提取由完整输入驱动的生产帧记录器，保留 Minecraft 与呈现为外层。
4. 将 `RawWavefrontFrame` 与 `PreparedNrdFrame` 保持为不同阶段类型；
   从 `NrdDenoiser` 分离输入准备、后端执行和合成。
5. 显式化 RNG、frame/history 状态与提交转移，清除队列顺序依赖和未定义 GPU 写入。
6. 增加阶段捕获、内容哈希与 replay 序列化，再建立低分辨率真实场景语义测试。

第一轮重构只改变边界、状态表达和可测试性，不主动改变积分器、采样分布、方差、偏差或
生产资源预算。任何物理图像拆分和新增稳态副本都需要单独的性能依据。
