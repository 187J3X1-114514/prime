# 渲染实现

本文记录 Prime 当前渲染器的稳定技术边界。历史调查、待办和实验方案分别放在调查报告、
`TODO.md`、`FIXME.md` 和未实施方案文档中。

## 渲染模式

### 实时路径追踪

实时模式每像素每帧通常生成一个物理样本。支持的 RTX 设备优先使用 DLSS Ray
Reconstruction；不可用或初始化失败时回退到 NRD-FSR。禁用后处理时以原生分辨率直接
显示 noisy color，不运行降噪或超分。

五档重建质量统一控制内部渲染尺寸。模式或尺寸变化会整体重建相关资源并重置不兼容的
时间历史。

### 参考累积截图

截图模式冻结相机、太阳、地形、灯光、相机介质和方块动画，在窗口原生分辨率累积线性
RGBA32F 运行均值。它旁路实时降噪、超分和调试覆盖层，不钳制高亮样本。

窗口纵横比变化会保留冻结的相机姿态、更新投影并重新累积；世界或资源切换会安全退出，
避免混合不同场景。

## 主积分器

- Vulkan KHR ray tracing pipeline，管线递归深度为 1；
- 实时与截图共用固定 12 轮的紧凑 wavefront 主积分器；
- head 创建路径，step/transition 推进活动路径，tail 处理稀疏长尾，resolve 适配输出；
- miss、closest-hit 和 any-hit 只返回遍历结果，不承担积分器状态机；
- 支持且真正提供 reorder 模式的设备可以使用
  `VK_EXT_ray_tracing_invocation_reorder`；
- 128 次反弹是异常长路径的安全上限，不是正常路径目标。

Russian roulette 在至少一次保证续接后开始。纯 delta 透明界面不执行 NEE，也不增加 RR
深度；粗糙或混合透明正常计数。太阳和方块面光源使用下一事件估计与
power-heuristic MIS。

`PathState`、`SurfaceInteraction`、BSDF、PDF、光源样本和采样维度是积分器契约。
wavefront 只保存状态并调度，不重新解释光传输数学。

## 透明与介质

首个可见表面为透明接口时，实时积分器固定追踪条件反射和条件透射两条路径并相加；后续
顶点恢复单路径采样，不继续递归分叉。两条路径共享首命中、材质翻译、闭包初始化和局部
视角计算。

玻璃、薄壁透明模型和水使用 RoboCute 介质透射 BSDF。零粗糙度材质按 Fresnel 采样 delta
反射或透射；非零粗糙度使用 GGX 重要性采样。薄壁材质使用光滑双界面级数，体积吸收按
射线实际经过的介质段计算。

介质栈固定保存两个非空气介质。空气 → 玻璃 → 水受支持；第三层实体介质和非 LIFO 边界
不在正确性契约内。相机初始介质目前只特殊识别水。

## 实时重建

### DLSS Ray Reconstruction

Prime 向 DLSS RR 提供 noisy color、Color Before Transparency、motion、depth、
normal/roughness、diffuse/specular albedo 和 specular hit distance。RR 是完整实时后端；
启用时不调度 NRD 或 FSR。

### NRD-FSR

NRD 使用主历史和透明反射历史处理普通表面、透明透射替代表面及反射支；太阳直射可通过
同一 NRD instance 的 SIGMA 过滤。去噪后的线性 HDR 结果交给 FidelityFX FSR 3.1.4
Upscaler。

运动向量采用 NRD 的非抖动 2.5D 屏幕空间约定：

```text
old = new + MV
```

XY 指向上一帧 UV，Z 是上一帧与当前帧 view-Z 之差。天空运动只包含相机旋转。FSR 复用
XY，并单独接收 reversed-infinite depth。

实时样本、NRD、FSR 和 DLSS 的历史都只在 GPU 提交成功后推进。图像首次布局状态以及
星图、BSDF LUT 等一次性上传同样在提交成功后发布；仅录制或被拒绝的命令缓冲不会污染
下一帧。世界、渲染原点、模式和不兼容尺寸变化会显式 reset。

## 材质

没有 PBR 数据时，不透明材质使用方块纹理与 biome tint，默认感知粗糙度为 0.90、介电
F0 为 0.04、IOR 为 1.5。显式材质数据优先。

LabPBR 1.3 当前使用：

- 感知光滑度与线性粗糙度；
- 介电 F0；
- 预定义和自定义金属；
- 次表面散射权重；
- 发光强度。

切线空间法线会读取并重建，但当前着色仍使用几何法线。AO、高度和孔隙率仅保留语义，
尚未接入遮蔽、位移或天气系统。辅助图集跟随原版 atlas 的 mip、padding、动画帧顺序和
插值进度；资源重载会原子替换图集并重建受影响 Section。

## 光照、颜色与显示

积分器、材质、光源、路径吞吐和截图累积统一使用 D65 白点的线性 Rec.2020。Minecraft
纹理和 tint 在材质边界从 sRGB 解码并转换。显示阶段通过 Oklab DRT 映射到 sRGB
Rec.709；显示变换不写回任何线性历史。

光源包括光谱大气、太阳、内嵌 Gaia 夜空和从原版发光等级及纹理估计的方块面光源。发光
材质进入灯光树、下一事件估计和 MIS。

物理着色点与 Vulkan 遍历偏移原点分离。路径坐标相对于 Prime 渲染原点，避免使用大尺度
绝对世界 `float` 坐标。

## 场景与资源

`render/terrain` 负责 Section 快照、异步网格化、virtual cluster、BLAS 驻留和 TLAS
替换。一个 4×4×4 Section virtual cluster 对应一个 BLAS、一个 TLAS instance、一个
世界灯光树叶和一个原子 generation。

CPU mesh 可以使用多个有界 segment，最终上传仍生成单个 BLAS。资源不足时不会提交不完整
generation，也不会静默丢弃几何。大型 primitive 数组由构建器把所有权移交给编译结果，
后续只读借用并零拷贝上传；不会为形式不可变复制完整地形。

`render/vulkan` 拥有 Vulkan handle、VMA 分配、同步、SBT、pipeline 和加速结构。资源采用
prepare/commit：下一驻留映射和 TLAS 描述先完整构造，命令被提交系统接受后再原子发布，
旧 BLAS/TLAS 和 staging 页按 Vulkan timeline 延迟销毁；渲染热路径不调用
`vkDeviceWaitIdle`。

Java/GLSL ABI、工作色彩空间和关键常量由 `shaders/abi.json` 统一声明并在构建时生成和
验证。

更一般的模块、状态和副作用规则见[纯函数式架构](纯函数式架构.md)。

## 诊断与重放

视频设置提供 NRD、FSR、DLSS RR、三角面分布和数值异常视图。数值异常诊断区分 NaN、
正负无穷、有限负值、非法方向、样本拒绝、单位范围及 FP16 上限。

`Ctrl+Alt+F10` 使用两套隔离历史运行 64×64 生产 wavefront 和 NRD 输入路径，检查语义并
比较同平台逐 bit 输出。通过的捕获保存在 `run/prime/replay/last-success.prseq`，默认不
进入版本库。

详细测试边界见[着色器属性测试与数值诊断架构](着色器属性测试与数值诊断架构.md)。
