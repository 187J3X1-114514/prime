# 渲染实现

本文概述当前稳定实现。透明数学、离线传输、场景流送和测试契约分别由对应专题文档维护；
仍开放的问题只记录在 [FIXME](FIXME.md)，未来增强只记录在 [TODO](TODO.md)。

## 渲染模式

### 实时

实时路径通常每像素每帧生成一个样本。`ReconstructionBackendRegistry` 固定提供三个内建
后端：DLSS Ray Reconstruction、NRD + FSR 和原生分辨率 Noisy。DLSS 能力、optimal-size
查询或 feature 创建失败时只回退 NRD-FSR；配置值不被静默改写。NRD/Noisy 创建失败保持
fail-fast。

五档质量由各后端 profile 解释：FSR profile 定义内部尺寸、mip、jitter 和 ray cone；
DLSS profile 定义 NGX quality、optimal query 与 RR jitter；Noisy 固定原生尺寸。语义
`RealtimeFramePlan` 不包含 Vulkan handle 或后端 native 类型。

### 离线累积截图

`OfflineRenderer` 冻结相机、天文、场景、材质、纹理 revision、相机介质和动态纹理列表，
在窗口原生分辨率累积 RGBA32F 运行均值。它旁路实时降噪与超分，并使用独立随机透明闭包和
全路径直接光估计；详细契约见[离线光传输契约](离线光传输契约.md)。

进入会话时复制实时显示通道的 16-byte 自动曝光状态，之后只读使用。最终曝光和显示曲线
可以即时调整，不修改累积样本。纵横比变化保留冻结姿态、更新投影并重新累积；世界或资源
切换会退出会话，避免混合不同场景。

## 积分器与透明

实时和离线使用各自的 KHR ray tracing pipeline、SBT、set 1 ABI 和 wavefront 状态，pipeline
递归深度为 1。miss、closest-hit 和 any-hit 只返回遍历结果，路径状态机由 wavefront 调度。
支持且实际提供 invocation reorder 的设备可以加载 SER raygen permutation。

太阳和方块面光源使用 NEE 与 power-heuristic MIS。发光面进入两级 world light tree；太阳
单独采样。路径状态、表面交互、BSDF、PDF、光源样本和采样维度是积分器契约，调度层不得
重新解释光传输数学。

实时透明为了稳定重建使用首接口双分支和后续确定性折射；玻璃为逐表面滤色，水进入最多两层
的体积栈并按实际路径长度吸收。离线不继承这套低方差近似。完整定义见
[透明渲染与实时重建](透明渲染与实时重建.md)。

## 重建与显示

DLSS RR 接收 noisy color、主/反射 motion、linear depth、normal/roughness 和
diffuse/specular albedo。Prime 不提供语义不真实的 Color Before Transparency 或 specular
hit distance。NRD 处理主历史、透明反射历史和太阳直射，输出再交给 FidelityFX FSR。

NRD motion 使用非抖动 2.5D 约定 `old = new + MV`；FSR 复用 XY 并单独接收
reversed-infinite depth。后端 debug 数据沿 runtime 到 Vulkan processor 的旁路传递，不进入
可序列化 frame plan。

所有后端生成全分辨率线性 Rec.2020 HDR 后进入统一显示边界。自动曝光在 GPU 上完成直方图、
目标与时间适应，正常路径不回读 CPU；最终曝光和 Oklab DRT 只改变显示结果，不写回实时历史
或离线累积。诊断叠加层的 16-byte 曝光读回只在队列完成回调发布。

## 材质与光照

缺少 PBR 数据时使用原版纹理和 biome tint，默认感知粗糙度为 0.90、介电 F0 为 0.04、
IOR 为 1.5。LabPBR 1.3 当前使用光滑度/粗糙度、介电 F0、金属、次表面权重和发光强度。
切线空间法线会读取，但着色仍使用几何法线；normal alpha 高度仅驱动可选纹理体素 relief，
AO 和孔隙率尚未参与着色。

积分器、材质、光源和累积统一使用 D65 线性 Rec.2020；Minecraft 纹理与 tint 在材质边界从
sRGB 解码并转换。光源包括光谱大气、太阳、Gaia 星空和由原版发光等级及纹理估计的方块面。
太阳与星图共享由 Minecraft 日角、观察纬度和固定季节构造的天文帧。

太阳 aerial perspective 的局部可见性来自 RT 世界空间方向光深度 clipmap。缓存按相机移动
增量更新，并在 terrain cluster 替换后重追踪受影响区域；截图在开始累积前完成当前方向。
它只近似单方向太阳体积阴影，不表示任意天空可见性、局部灯光体积阴影或参与介质多次散射。

## 场景与资源

地形链分为三层：

- `render.runtime.terrain`：`TerrainStreamer` 的 desired/current、资源 epoch、worker 调度和上传；
- `render.terrain`：捕获值到 CPU mesh、OMM、发光分布和 light tree 的纯翻译；
- `render.vulkan.terrain`：staging、resident cluster、BLAS/TLAS 与 compaction。

Minecraft/Fabric 只在 `render.scene.vanilla` 边界被观察，并转换为 `CapturedSectionGeometry`、
`SpriteId` 和 `CapturedSprite`。一个对齐的 4×4×4 Section cluster 作为原子 generation 替换；
CPU mesh 可分段构建，但不会发布不完整 generation。详见
[区块簇场景翻译架构](区块簇场景翻译架构.md)。

Prime 与原版 terrain 互斥驻留。启用 Prime 时释放原版 dispatcher、uber buffer 和 staging
资源；关闭时先完整退休 Prime renderer，再按原版上限重新建立 vanilla terrain。扩展视距
只用于集成服务器，远程连接和原版路径仍限制为 32。

`TraceBackend` 拥有共享 descriptor、BSDF LUT、星图和提交资源；实时与离线 renderer 各自
拥有 pipeline、wavefront 和分辨率相关资源。`TraceBindings` 提供 descriptor 就绪契约，
`SunShadowPipeline` 不持有整个 backend。GPU 属性探针位于 `render.vulkan.replay`，基础
`VulkanContext` 不依赖 replay。

## 状态发布

帧和资源都采用 prepare/accept：计划与候选资源先完整构造，`encoder.execute()` 正常返回
表示已被 Minecraft host submission 接受，此时才推进 Prime history、图像初始化和 resident
映射。execute 前失败执行 abandon；execute 后宿主失败则 runtime 进入 `FAILED` 并退休
renderer。旧 GPU 资源按 timeline 延迟销毁，热路径不调用 `vkDeviceWaitIdle`。

Java/GLSL ABI、工作色彩空间和关键常量由 `shaders/abi.json` 统一声明并在构建时生成和验证。
更一般的依赖和状态规则见[架构与数据流](纯函数式架构.md)。

## 诊断与 replay

设置界面提供 NRD、FSR、DLSS RR、三角面分布和数值异常视图。Renderer Diagnostics 报告活动
路径、内部/显示分辨率、累积样本、GPU 能力、TLAS/BLAS、面光源、light tree 和 compaction。

`Ctrl+Alt+F10` 使用隔离历史运行 64×64 生产 wavefront 和 NRD 输入路径，做语义检查与同平台
逐 bit 比较。通过的捕获写入 `run/prime/replay/last-success.prseq`；失败时保存 reference 和
replay 两份序列。codec v4 的模式 wire code 和已有 fixture 保持兼容。测试边界见
[着色器属性测试与数值诊断架构](着色器属性测试与数值诊断架构.md)。
