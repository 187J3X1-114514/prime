# 已知问题

本页只记录当前可复现缺陷和明确接受的限制。已修复问题不在这里保留历史流水；重新出现时应
附日志、资源包/mod 组合、复现步骤，以及问题首次出现的渲染阶段。

## 动态实体

### 实体闪烁与拖影

实体可能出现时间性闪烁，运动时还可能留下轻微历史拖影。应先区分动态 mesh 捕获、BLAS/TLAS
发布、motion/disocclusion 和 NRD/RR history，不能从最终画面直接归因于降噪器。

### 物品展示框不渲染

展示框或其中的物品可能缺失。需分别检查实体/内容 mesh、render type、动态 BLAS 和 TLAS
instance 可见性。

### 史莱姆不透明

当前实体材质不能表达史莱姆的半透明、内部散射和柔软质感。不能仅按实体类型硬编码透明度；
完整方案需要同时定义材质适配、采样和重建 guide。

## 光照与介质

### 水下阴影缺失

浅水中也可能看不到预期遮挡阴影。需对照相机在水上/水下时的主光可见性、shadow ray 水面
穿越、介质透射和最终组合。

### 信标光柱遮光

信标光柱可能被 shadow/visibility 路径当成不透明遮挡。光柱应保持可见，但不能阻断照明；
需核对动态 mesh、材质分类和 shadow any-hit。

### 水与玻璃的艺术表现

当前物理传输可用，但水面、水下、建筑玻璃、染色玻璃和长玻璃链的材质表现仍未达到最终
目标。调整应位于 Prime 材质翻译、吸收、粗糙度、normal 和 reconstruction guide；不得借此
修改受保护 RoboCute BSDF 或重新引入未预算的实时传输算法。

## 模型与资源包

### Better Leaves

Better Leaves 的落叶内容可能错误。需从捕获几何、纹理 alpha、材质标志和 OMM 输入逐级确认，
目前不能断言根因就是 OMM。

### 红石火把

部分资源包的红石火把头部应为 alpha-cut 独立平面，Prime 可能将其捕获为不透明几何。后续
调查应以实际 baked quad、sprite alpha、材质标志和 OMM 输入为证据，不能只依赖方块 ID 或
Minecraft render layer。

### 纹理体素 relief 遮挡附着内容

向外生成的体素柱可能遮住发光地衣、火焰等贴近宿主表面的独立内容。需区分宿主表面、贴花层
和交叉面，再决定跟随 relief、有界外移或回退标准 quad；禁止使用无上限全局偏移。

## 性能

### 高视距地形流送的分配与 TLAS 成本

在较小 Java 堆、高视距且持续跑图时，Section→cluster 中间存储和全 resident TLAS 更新仍可能
造成高分配率、GC 停顿和帧率下降。已完成紧凑 light tree、有界 CPU segment、跨世界统一
in-flight 上限和 64 MiB 上传/compaction 背压，但仍需实机测量稳态分配、GC、TLAS build 与
长期帧时间。增大 `-Xmx` 只能临时延后问题。

后续优化不得丢弃 geometry、放宽无界队列、在热路径调用 `System.gc()`，也不得用增加 TLAS
instance 换取较低上传峰值。

## 明确接受的限制

- 透明介质栈最多容纳两个非空气区域；第三层嵌套、非流形边界或缺失界面的吸收/pop 顺序不受
  保证。后续完整闭包的非薄壁玻璃折射可占用一个零吸收 IOR 栈项，但玻璃颜色仍只逐面滤色。
- 实时透明使用首接口 50/50 棋盘格单分支、后续完整闭包随机单分支和直线 NEE 滤光；它仍
  不是任意折射链的无偏连接。
- 玻璃按实际表面逐次滤色，相接方块保留的内部面也会继续贡献滤色。
- 太阳体积阴影只近似单方向太阳可见性，不表示半球天空、局部灯光或参与介质多次散射。
