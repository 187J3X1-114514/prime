# 构建与验证

## 环境

- JDK 25；
- Vulkan SDK 1.4.350；
- SDK 中可用的 `glslangValidator` 与 `spirv-val`。

Windows PowerShell 示例：

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-25.0.2'
$env:VULKAN_SDK = 'C:\VulkanSDK\1.4.350.0'
$env:Path = "$env:JAVA_HOME\bin;$env:VULKAN_SDK\Bin;$env:Path"
.\gradlew.bat clean build
```

## 开发运行

```powershell
.\gradlew.bat runClient
```

默认开发配置使用 Vulkan 并启用 validation。验证 Prime 在 OpenGL 下不接管渲染：

```powershell
.\gradlew.bat runClient -PprimeBackend=opengl
```

不要使用 Gradle `--args` 覆盖图形后端；Loom 会将它与已有参数合并。

## Shader 构建

`compileShaders` 编译 Prime shader，并从统一源码生成普通和 SER raygen permutation。
运行时只在设备报告有效 invocation reorder 能力时加载 SER。

发布构建会：

- 剥离 SPIR-V 调试信息；
- 执行保持语义的结构化简；
- 再次运行 `spirv-val`；
- 将结果写入 JAR。

Nsight 调试需要源码映射时使用：

```powershell
.\gradlew.bat compileShaders -PprimeShaderDebug=true
```

临时 SPIR-V 位于 `build/`。发行 JAR 内置 Windows x86-64 的 NRD、FidelityFX 和 DLSS RR
运行库，不包含 NVIDIA development DLL、DLSS Super Resolution 或 Frame Generation。

## 测试

常规完整回归：

```powershell
.\gradlew.bat test compileShaders verifyDistributionJar shaderTest
```

主要任务：

- `test`：Java、ABI、状态机、codec 和数学性质；
- `compileShaders`：编译并验证生产 shader；
- `shaderTest`：在 Vulkan compute 设备上运行真实 GLSL 属性测试；
- `verifyDistributionJar`：检查发行 JAR 的资源、许可、shader 和 native 库。

Windows x86-64 测试会实际加载 NRD、FidelityFX 和 DLSS RR 桥接库并验证 ABI。其他平台
跳过 Windows native 执行，但仍编译 Java/shader 并检查 JAR。

GPU replay fixture：

```powershell
.\gradlew.bat validateReplayFixture -PprimeReplayFixture=<fixture>

.\gradlew.bat compareReplayFixtures `
  -PprimeReplayExpected=<reference> `
  -PprimeReplayActual=<actual>
```

fixture 使用显式版本、SHA-256 完整性校验和 256 MiB 读取上限。
`Ctrl+Alt+F10` 的失败诊断会把两套隔离执行保存到
`run/prime/replay/last-failure-reference.prseq` 和
`run/prime/replay/last-failure-replay.prseq`；日志会记录规范化后的绝对路径。

## CI

GitHub Actions 在 Ubuntu 24.04 上使用 JDK 25、Vulkan SDK 1.4.350 和 Mesa Lavapipe，运行：

```text
clean build shaderTest
```

CI 会保存失败测试报告，并上传构建生成的 JAR。
